# 주간 전년비 정합성 및 대시보드 전체 AI 실적문의 설계

## 목표

`first-dashboard`의 기존 지표 정의와 필터 계산식을 바꾸지 않으면서 다음 두 문제를 함께 해결한다.

1. 최신 주가 7일 미만인 경우 주별 전년비가 일별 동기간·동요일 전년비와 달라지는 오류를 수정한다.
2. 브라우저 안에서 동작하는 AI 실적문의가 대시보드에서 확인할 수 있는 실적과 조건을 빠짐없이 조회하도록 확장한다.

별도 생성형 AI API는 필수로 도입하지 않는다. 자연어는 규칙 기반으로 해석하고, 답변 수치는 대시보드의 공식 계산 함수와 업로드한 백업 데이터에서만 계산한다.

## 변경하지 않는 기준

- 첫구매, 앱, KPI, 상품 지표의 정의와 단위는 기존 대시보드를 따른다.
- 전년 비교는 364일 전의 동일 요일을 사용한다.
- 완결된 주간의 비회원 트래픽, 가입자 수, 첫구매율은 기존 주간 중복 제거 원천값을 사용한다.
- 월별·일별 누계와 비율 지표 재계산 방식은 유지한다.
- 질문이나 계산 결과는 서버로 전송하거나 브라우저 저장소에 저장하지 않는다.
- `first-dashboard`만 수정하며 다른 대시보드 데이터나 코드를 섞지 않는다.

## 1. 부분 주차 전년비 수정

현재 주별 화면은 최신 주에 하루만 있어도 현재 값은 하루치인데, 전년도 트래픽 계열 지표는 7일 전체의 주간 중복 제거값을 사용한다. 이 때문에 일별 9/21과 주별 9월 4주차가 서로 다른 비교값을 표시한다.

주차에 포함된 현재 데이터가 7일 미만이면 해당 주차를 `부분 주차`로 본다. 부분 주차에서는 현재와 비교 기간 모두 실제 포함된 날짜 목록으로 계산한다. 따라서 하루만 있으면 당일과 364일 전 동일 요일을 비교하고, 3일이면 같은 요일 3일을 비교한다. 7일이 모두 있는 완결 주차는 기존 주간 중복 제거 계산을 그대로 사용한다.

검증 항목은 다음과 같다.

- 실제 2026-09-21 백업에서 주별 최신 주의 전년도 값과 일별 9/21의 전년도 값이 일치한다.
- 거래액, 고객수, 객단가, 트래픽, 가입자, 전환율 등 관련 지표가 같은 비교 날짜 집합을 사용한다.
- 완결 주차는 수정 전후 값이 변하지 않는다.

## 2. 자연어 기간 해석

다음 표현을 모두 지원한다.

- 날짜: `2026년 9월 21일`
- 날짜 범위: `24년 추석 9월 14-18`, `2025년 10월 3일~9일`
- 월: `24년 9월`, `2026년 9월 비교`
- 대시보드 주차: `24년 9월 3주차`, `2025년 9월3주차`
- 여러 기간: 쉼표, 줄바꿈, `와`, `및`, `대비`로 연결된 2개 이상의 기간

주차는 대시보드와 동일하게 월요일부터 일요일까지이며, 그 주의 목요일이 속한 월과 해당 월의 몇 번째 목요일인지로 라벨을 정한다. 예를 들어 `2026년 9월 3주차`는 2026-09-14~2026-09-20이다.

`추석`, `행사`, `프로모션` 같은 단어는 사용자가 붙인 기간 이름으로 취급한다. 특정 행사만 하드코딩하지 않으며, 함께 입력한 날짜나 주차가 실제 계산 범위를 결정한다.

## 3. 조회 가능한 지표와 조건

### 첫구매 실적

기존 첫구매 핵심 지표 전체를 지원한다. 거래액, 고객수, 객단가, 비회원 트래픽, 가입자, 첫구매 전환율 등 화면의 공식 지표 이름과 일반적인 축약 표현을 같은 지표로 인식한다.

회원구분과 채널 조건은 질문에 명시하면 적용하고, 명시하지 않으면 현재 화면의 필터를 상속한다.

### 상품 실적

다음 조건과 구분을 지원한다.

- 채널
- BPU
- 카테고리
- 브랜드
- 상품

`채널별`, `BPU별`, `카테고리별`, `브랜드별`, `상품별` 또는 `채널/BPU/카테고리까지`라고 물으면 요청한 차원의 상세 내역을 함께 계산한다. 명시하지 않은 상품 조건은 현재 화면의 선택값을 상속한다.

상품 상세는 기존 상품 원천 데이터의 거래액·고객수·객단가 계산을 사용한다. UV·CR처럼 특정 집계 수준에서만 제공되는 지표는 원천 데이터가 지원하는 차원에서만 표시하고, 지원되지 않는 조합은 값을 추정하지 않고 사유를 명시한다.

### 앱·푸시·회원 실적

앱 신규 설치, 앱 방문·재방문·삭제·순증, 앱 기기, 푸시 동의/미동의와 회원 관련 화면 지표를 기존 `AX` 계산식으로 조회한다. 질문에 지표가 명시되면 해당 지표를, `앱 실적 전체`처럼 요청하면 앱 영역의 요약을 반환한다.

### KPI

연간 KPI의 실적, 목표, 달성률, 전년, 일평균, 필요 실적 등 화면에 표시되는 값을 기존 `computeKpi` 결과로 조회한다. 백업에 목표 데이터가 없으면 목표·달성률을 임의 생성하지 않고 데이터 없음으로 표시한다.

## 4. 질문 의도와 기본 동작

- 지표를 명시한 질문은 해당 지표 중심으로 답한다.
- 지표 없이 기간만 비교하면 첫구매 핵심 지표 요약을 기본으로 답한다.
- `전체 실적`, `모든 실적`이라고 요청하면 첫구매, 앱·회원, KPI, 상품 요약을 모두 포함한다.
- 조건을 명시하지 않으면 현재 대시보드 필터를 상속하고, 답변 상단에 실제 적용 조건을 표시한다.
- 질문의 조건과 현재 화면 필터가 충돌하면 질문에 명시한 조건을 우선한다.
- 데이터 범위를 벗어난 기간은 사용 가능한 날짜로 조용히 바꾸지 않고, 누락 범위를 명확히 알린다.

## 5. 답변 구성

답변은 기존 대시보드 UI를 해치지 않도록 현재 접힘 패널 안에서 표시한다.

1. 적용 기간과 필터
2. 핵심 비교 요약
3. 기간별 지표 표
4. 요청한 차원별 상위 항목
5. 14일 전 권장 액션 시작일과 과거 패턴 기반 예상 방향
6. 접힌 상세 표

차원별 결과가 많으면 전체 합계와 상위 항목을 먼저 표시하고, 전체 목록은 기본 접힘 상태로 제공한다. 예상은 확정 예측이 아니라 과거 패턴을 이어 본 참고값임을 계속 표시한다.

## 6. 구현 구조

`ai_question.js`는 자연어 해석과 답변 조립을 담당한다. 실제 수치는 `dashboard.html`이 노출하는 읽기 전용 어댑터를 통해 계산한다.

- 첫구매: 기존 `compute`, `monthCols`, `weekCols`, `dayCols`
- 앱·회원: 기존 `axVal`, `AX`, `AX_ORDER`
- KPI: 기존 `computeKpi`
- 상품: 원천 상품 행을 현재 필터와 질문 필터로 집계하는 읽기 전용 질의 함수

어댑터는 현재 화면 상태를 변경하지 않는다. 질문 실행으로 필터, 선택 항목, 그래프 또는 업로드 데이터가 바뀌어서는 안 된다.

## 7. 오류 처리

기존의 `BPU/카테고리/상품은 지원하지 않음` 차단 문구는 제거한다. 오류는 다음 상황에만 표시한다.

- 계산할 기간을 전혀 특정할 수 없음
- 요청 기간이 업로드 데이터 범위를 벗어남
- 해당 백업에 필요한 원천 데이터가 없음
- 문장이 둘 이상의 방식으로 해석되어 결과가 달라지는 실제 모호성

이 경우에도 가능한 조건과 수정 예시를 같이 보여준다.

## 8. 검증 및 배포

- 자연어 파서 단위 테스트: 날짜, 월, 주차, 다중 기간, 차원·지표 별칭
- 계산 회귀 테스트: 부분 주차와 완결 주차, 핵심 지표, 앱, KPI, 상품 차원
- 실제 2026-09-21 백업을 사용한 브라우저 검증
- 기존 대시보드 스모크 테스트와 자바스크립트 문법 검사
- 로컬 화면에서 질문 패널과 접힘 상세 확인
- 모든 검증 통과 후 `main`에 배포하고 공개 페이지에서 재확인
